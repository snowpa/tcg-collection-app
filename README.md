# トレカ・コレクション

トレーディングカードの所持・状態・コンプ率を管理する、GitHub Pages で動く静的 Web アプリです。
[mercari-gas-parser](../mercari-gas-parser/) の「Gmail の購入メール → カード名推定 → 一覧化」の機能を取り込み、DMM マイカのようなコレクション管理画面を付けています。

- サーバー不要。データはブラウザの IndexedDB に保存されます
- バックアップ先は **Google ドライブ** と **ローカル（JSON / 自動保存ファイル）**
- 外部ライブラリなし（素の HTML / CSS / JavaScript）、PWA 対応でスマホのホーム画面に追加できます

## 機能

| 画面 | 内容 |
| --- | --- |
| ホーム | 購入総額・所持枚数・状態チェック済み数、状態評価の内訳、要注意のカード（折れ・へこみ等）、購入額の推移、最近追加したカード |
| コレクション | グリッド（バインダー風）とリスト表示、検索、セット・レアリティ・鑑定・状態・タグでの絞り込み、並び替え |
| カード詳細 | 画像（撮影/アップロード、自動縮小）、セット・番号・鑑定(PSA など)・枚数・購入情報、AI によるカード判定、**状態チェック**（下記） |
| セット | セットコードと番号（例 `198/190`）から自動でコンプ率を集計。分母を超える番号はシークレットとして別カウント。収録数はセット登録で上書き可 |
| ほしいもの | 目標価格つきで登録。「入手した」で所持に移動 |
| 取り込み | Gmail の購入完了メール（メルカリ / Yahoo! / 楽天ラクマ / magi / スニダン）を解析して候補を一覧表示 → 選択して追加。旧スプレッドシートの CSV 取り込み |
| 設定 | Google 連携、Gemini、キーワードフィルタ、検索クエリ、バックアップ |

### 状態チェック

カード詳細の「状態チェック」で、1枚ごとに次を記録できます。

- **総合評価**: S（完美品）／A（美品）／B（小傷あり）／C（傷・白かけが目立つ）／D（ダメージ大）と点検日
- **センタリング**: 表・裏それぞれ上下左右の枠の幅（mm でも目盛りでも可）を入れると「左55 : 右45」のように比率を計算し、PSA10 の目安（表 55:45・裏 75:25 以内）に収まるかを表示
- **欠陥**: 白かけ・へこみ・折れ・表面傷・ホロ傷・汚れ/シミ・印刷ズレ/初期傷・反り を「なし／軽微／目立つ／重度」で記録
- **白かけの位置**: 表・裏のカード図で角4か所・辺4か所をタップして記録
- **詳細メモ** と **状態の写真**（1枚につき8枚まで、自動縮小）

一覧では状態評価のバッジと「要注意」の件数が表示され、「状態」で絞り込み（評価別・未評価・欠陥あり・折れ/へこみあり・センタリング基準外）や「状態が良い順」の並び替えができます。CSV 書き出しにも状態チェックの列が含まれます。

### mercari-gas-parser との対応

| GAS 版 | このアプリ |
| --- | --- |
| `GmailApp.search` で5種類のメールを検索 | Gmail API（`gmail.readonly`）で同じクエリを検索。クエリは設定画面で編集可 |
| `extractItemName` / `extractPrice` / `extractMercariId` | `js/parser.js` にそのまま移植 |
| `KEYWORDS` / `EXCLUDE_KEYWORDS` / `ENABLE_KEYWORD_FILTER` | 設定画面の「取り込みフィルタ」 |
| `processed_mercari` ラベルで処理済み管理 | アプリ内でメール ID を記録（Gmail には書き込まない） |
| メールリンクで重複チェック | メール ID とメールリンク（スレッドID）で重複チェック。旧スプレッドシートから取り込んだ分も重複扱い |
| Gemini で正式名称を推定（画像あり/なし、`SKIP`） | 同じプロンプトを JSON 出力に変更し、カード名・レアリティ・セット・番号に分けて保存。対象外は「AI判定: 対象外」 |
| スプレッドシートに追記 | IndexedDB に保存。CSV 書き出し可 |

メルカリの商品画像は直リンクで表示します。Gemini へ画像を送るには画像のダウンロードが必要ですが、ブラウザの CORS 制限で取得できない場合は商品名のみで判定します。カード詳細で自分で撮った写真を登録すれば、その画像で判定できます。

## 1. GitHub Pages に公開する

1. GitHub で新しいリポジトリを作成（例: `tcg-collection`）
2. このフォルダの中身（`index.html`, `style.css`, `js/`, `sw.js`, `manifest.json`, `icon.svg`）をアップロード
3. リポジトリの **Settings → Pages** で、Source を「Deploy from a branch」、ブランチを `main` / `/(root)` にして保存
4. 数分後に `https://<ユーザー名>.github.io/tcg-collection/` で開けます

この時点で、手動登録・CSV/JSON 入出力・ローカル自動保存は使えます。

### PC で動作確認する場合

`index.html` をダブルクリックで開くと ES モジュールや IndexedDB が動きません。簡易サーバーを使ってください。

```bash
cd tcg-collection-app
python -m http.server 8000
# → http://localhost:8000/ を開く
```

## 2. Google 連携（Gmail 取り込み・ドライブ保存）

Google Cloud Console で OAuth クライアントを1つ作ります（無料）。

1. https://console.cloud.google.com/ で新しいプロジェクトを作成
2. **API とサービス → ライブラリ** で **Gmail API** と **Google Drive API** を有効化
3. **OAuth 同意画面**（Google Auth Platform）を設定
   - User Type: 外部 / アプリ名・メールアドレスを入力
   - スコープ: `gmail.readonly` と `drive.file` を追加
   - **テストユーザー** に自分の Gmail アドレスを追加（公開ステータスは「テスト」のままで OK）
4. **認証情報 → 認証情報を作成 → OAuth クライアント ID**
   - 種類: **ウェブ アプリケーション**
   - 承認済みの JavaScript 生成元: `https://<ユーザー名>.github.io`（ローカル確認するなら `http://localhost:8000` も）
   - リダイレクト URI は不要
5. 表示された **クライアント ID**（`xxxx.apps.googleusercontent.com`）をアプリの「設定 → Google 連携」に貼り付け

> テスト状態のアプリでは、ログイン時に「Google はこのアプリを確認していません」と表示されます。自分で作ったアプリなので「続行」で進めてください。
> クライアント ID は公開されても問題ない値です（シークレットは不要・使用しません）。

### スコープについて

- `gmail.readonly` … 購入メールの読み取りのみ。メールの変更・送信はしません
- `drive.file` … このアプリが作成したファイル（`tcg-collection-backup.json`）にだけアクセスします。他のドライブのファイルは見えません

## 3. Gemini（任意）

1. https://aistudio.google.com/apikey で API キーを作成
2. 「設定 → AI（Gemini）」に貼り付け。モデル名は既定で `gemini-2.5-flash`（使えなくなったら新しいモデル名に変更）

API キーはその端末のブラウザ（localStorage）にのみ保存され、バックアップファイルには含まれません。

## バックアップと復元

状態の写真はバックアップに含まれるため、写真が多いとバックアップファイルが大きくなります。

| 方法 | 使い方 |
| --- | --- |
| Google ドライブ | 右上の「バックアップ」ボタンか設定画面の「ドライブに保存」。一度ログインすると、その後1時間は変更のたびに自動保存（設定で OFF 可） |
| ローカル自動保存 | PC版 Chrome / Edge で「自動保存するファイルを指定」。以後は変更のたびに上書き。OneDrive 等の同期フォルダ内を指定すると二重の備えに |
| JSON | 「JSON を書き出す」で手動保存。スマホではこちら |
| CSV | Excel / スプレッドシートで見る用 |

- **マージ**: 両方のデータを合わせます。同じカードは更新日時が新しい方を採用（削除も反映）。複数端末での同期に使えます
- **上書き復元**: 端末のデータをバックアップの内容で置き換えます

ホーム画面には、7日以上バックアップしていない場合に通知が出ます。

### 旧スプレッドシートからの移行

スプレッドシート「ポケモンカード購入履歴」を **ファイル → ダウンロード → CSV** で保存し、「取り込み → CSV から取り込む」で読み込みます。
「予測名称」列（例: `マリィ (SR, S4a シャイニースターV, 198/190)`）はカード名・レアリティ・セット・番号に分解されます。
メールリンクが一致するメールは、以後 Gmail スキャンでも「取込済み」として扱われます。

## ファイル構成

```
tcg-collection-app/
├── index.html      画面の枠
├── style.css       デザイン（ライト/ダーク対応）
├── js/
│   ├── app.js      画面描画・データ操作・バックアップ
│   ├── db.js       IndexedDB ラッパー
│   ├── parser.js   購入メールの解析（GAS版から移植）
│   ├── google.js   Google ログイン・Gmail・Drive API
│   ├── gemini.js   Gemini によるカード判定
│   └── chart.js    折れ線グラフ（SVG）
├── sw.js           オフライン用 Service Worker
├── manifest.json   PWA 設定
└── icon.svg        アイコン
```

更新を配信したときにスマホで古い画面が出る場合は、`sw.js` の `CACHE` のバージョンを上げてください。
