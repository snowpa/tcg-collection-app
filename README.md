# トレカ・コレクション

トレーディングカードの所持・状態・コンプ率を管理する、GitHub Pages で動く静的 Web アプリです。
[mercari-gas-parser](../mercari-gas-parser/) の「Gmail の購入メール → カード名推定 → 一覧化」の機能を取り込み、DMM マイカのようなコレクション管理画面を付けています。

- サーバー不要。データはブラウザの IndexedDB に保存されます
- バックアップ先は **Google ドライブ** と **ローカル（JSON / 自動保存ファイル）**
- 外部ライブラリなし（素の HTML / CSS / JavaScript）、PWA 対応でスマホのホーム画面に追加できます

## 機能

| 画面 | 内容 |
| --- | --- |
| ホーム | 購入総額・所持枚数・状態チェック済み数、状態評価の内訳、要注意のカード（折れ・へこみ等）、購入額の推移、最近追加したカード |
| コレクション | グリッド（大・中・小）とリスト表示、セットごとのグループ表示、AND 検索、絞り込み、並び替え、複数選択での一括編集・削除 |
| カード詳細 | 画像（撮影/アップロード、自動縮小）、セット・番号・鑑定(PSA など)・枚数・購入情報、AI によるカード判定、**状態チェック**（下記） |
| 鑑定候補 | カードラッシュの美品と PSA10 の価格差（倍率・差額・鑑定費用差引）が大きいカードを、手持ちとキーワード検索から探す |
| ほしいもの | 目標価格つきで登録。「入手した」で所持に移動 |
| 取り込み | Gmail の購入完了メール（メルカリ / Yahoo! / 楽天ラクマ / magi / スニダン）を解析して候補を一覧表示 → 選択して追加。旧スプレッドシートの CSV 取り込み |
| 設定 | Google 連携、Gemini、キーワードフィルタ、検索クエリ、バックアップ |

### たくさんのカードを扱うために（100〜1000枚想定）

- **表示**: 一覧は60件ずつ描画し、スクロールで続きを読み込みます。一覧には自動で作る小さなサムネイルを使います。状態写真は別の保存領域に分けてあり、カードを開いたときだけ読み込みます
- **探す**: 検索は空白区切りの AND 検索です（例: `リザードン SAR`）。`/` キーで検索欄に移動します。「絞り込み」パネルの条件はチップで表示し、× で個別に解除できます。リスト表示では列見出しをクリックして並び替えられます（もう一度押すと昇順/降順が入れ替わります）
- **見渡す**: 「セットごと」にチェックするとセット単位の見出しでまとめて表示します。グリッドの大きさは大・中・小を選べます。表示形式・並び順・絞り込みは端末に記憶されます
- **まとめて直す**: 「選択」でカードを複数選び（「表示中をすべて選択」も可）、一括編集（区分・状態評価・点検日・セット・鑑定・購入先・購入日・タグの追加/削除）や一括削除ができます
- **1枚ずつ点検する**: 一覧から開いたカードは、‹ › ボタンか ←/→ キーで前後のカードに移動できます。「保存して次へ」で、状態チェックを順に進められます
- **続けて登録する**: 新規登録の「保存して続けて追加」は、セット・購入先・購入日を引き継いで次の1枚を入力できます。同じセット・番号・鑑定のカードが登録済みの場合は、枚数をまとめるかどうか確認します
- **バックアップ**: 写真を含めて数十MBになっても保存できるよう、Google ドライブへは分割アップロード（resumable upload）で送ります。自動バックアップは編集が落ち着いてから（約30秒後、または画面を離れたとき）行います

### 鑑定候補（美品と PSA10 の価格差）

「鑑定候補」タブで、カードラッシュの **美品（無印）** と **PSA10鑑定済** の販売価格を比べ、PSA 鑑定に出すと値上がりが大きいカードを探せます。

- **手持ちのカード**: 相場の取得で保存した価格一覧から計算します（通信なし）。状態評価とセンタリングの目安も並べて表示します。鑑定済みのカードは初期状態では除外します
- **カードラッシュで探す**: キーワード（例: SAR、マリィ、ポケモンカード151）で検索し、結果を同じカードごとにまとめて表示します（1回で最大100件。「さらに100件読み込む」で追加）
- 倍率 = PSA10 ÷ 美品、差額 = PSA10 − 美品、鑑定費用差引 = 差額 − 鑑定費用（初期値 4,000円、画面で変更可）。倍率順・差額順で並べ替えられ、金額からカードラッシュの商品ページを開けます
- PSA10 が取れるとは限らないので、状態やセンタリングも合わせて判断してください

### 未開封BOX・パック

カード詳細の「種類」を **未開封BOX・パック** にすると、BOX・パック・デッキなどの未開封商品も同じコレクションに登録できます。

- 入力欄は「商品名・型番・セット名・形態（BOX / パック / デッキ / その他）・個数・購入価格（1個）」になり、レアリティ・番号・鑑定は使いません。未開封は常にオンです
- 状態チェックは総合評価・ひとこと・詳細メモ・写真だけです（センタリング・欠陥・白かけはありません）
- 相場はカードラッシュの【未開封BOX】【未開封パック】などの商品のうち、**形態が同じもの**から計算します（〔状態A-〕なども総合評価に合わせて使用）。商品名が完全に一致しない場合は、商品名と型番の両方を含む商品が1種類に決まれば使います（例: 「ポケモンカード151」＋型番「SV2a」→ 強化拡張パック『ポケモンカード151』(SV2a)）。確実に照合するには「🔎 カードラッシュから取得」で商品を選んでください（形態も自動で入ります）
- 一覧では「BOX」バッジが付き、絞り込みの「種類」で分けられます。ホームの所持数は「カード ○枚・BOX等 ○個」に分かれ、状態チェックの集計はカードのみです
- 商品名に「拡張パック」「強化拡張パック」「BOX」「スタートデッキ」「○パック」などがあり、番号やレアリティ（SR・SAR・PSA など）がない場合は未開封商品と判断します。CSV・Gmail の取り込みでは自動で BOX にし、カード詳細ではカードのままなら「未開封BOX・パックにする」ボタンを表示します（以前に登録したデータも起動時に一度だけ移行）

### 状態チェック

カード詳細の「状態チェック」で、1枚ごとに次を記録できます。

- **未開封**: 透明パック入りのプロモなど未開封のカードにチェック（カード詳細の基本情報）。一覧に「未開封」バッジが付き、「状態」の絞り込み・一括編集・CSV にも対応。カードラッシュの【未開封パック】【未開封BOX】やフリマの商品名に「未開封」があれば自動でチェックが入ります
- **総合評価**: S（完美品）／A（美品）／B（小傷あり）／C（傷・白かけが目立つ）／D（ダメージ大）と点検日
- **センタリング**: 表・裏それぞれ上下左右の枠の幅（mm でも目盛りでも可）を入れると「左55 : 右45」のように比率を計算し、PSA10 の目安（表 55:45・裏 75:25 以内）に収まるかを表示
- **欠陥**: 白かけ・へこみ・折れ・表面傷・ホロ傷・汚れ/シミ・印刷ズレ/初期傷・反り を「未確認／なし／軽微／目立つ／重度」で記録。新しいカードは「未確認」から始まり、「未確認の項目を『なし』にする」ボタンでまとめて確認済みにできます（一括編集でも可）。「状態」の絞り込みで「欠陥に未確認の項目あり」のカードを探せます
- **白かけの位置**: 表・裏のカード図で角4か所・辺4か所をタップして記録
- **詳細メモ** と **状態の写真**（1枚につき8枚まで、自動縮小）

一覧では状態評価のバッジと「要注意」の件数が表示され、「状態」で絞り込み（評価別・未評価・欠陥あり・折れ/へこみあり・センタリング基準外）や「状態が良い順」の並び替えができます。CSV 書き出しにも状態チェックの列が含まれます。

### mercari-gas-parser との対応

| GAS 版 | このアプリ |
| --- | --- |
| `GmailApp.search` で5種類のメールを検索 | Gmail API（`gmail.readonly`）で同じクエリを検索。クエリは設定画面で編集可 |
| `extractItemName` / `extractPrice` / `extractMercariId` | `js/parser.js` にそのまま移植 |
| `KEYWORDS` / `EXCLUDE_KEYWORDS` / `ENABLE_KEYWORD_FILTER` | 設定画面の「取り込みフィルタ」 |
| `processed_mercari` ラベルで処理済み管理 | アプリ内でメール ID を記録（Gmail には書き込まない） |
| メールリンクで重複チェック | メール ID とメールリンク（スレッドID）で重複チェック。旧スプレッドシートから取り込んだ分も重複扱い |
| Gemini で正式名称を推定（画像あり/なし、`SKIP`） | 同じプロンプトを JSON 出力に変更し、カード名・レアリティ・セット・番号に分けて保存。対象外は「AI判定: 対象外」 |
| スプレッドシートに追記 | IndexedDB に保存。CSV 書き出し可 |

メルカリの商品画像は直リンクで表示します。Gemini へ画像を送るには画像のダウンロードが必要ですが、ブラウザの CORS 制限で取得できない場合は商品名のみで判定します。カード詳細で自分で撮った写真を登録すれば、その画像で判定できます。

## 1. GitHub Pages に公開する

1. GitHub で新しいリポジトリを作成（例: `tcg-collection`）
2. このフォルダの中身（`index.html`, `style.css`, `js/`, `sw.js`, `manifest.json`, `icon.svg`）をアップロード
3. リポジトリの **Settings → Pages** で、Source を「Deploy from a branch」、ブランチを `main` / `/(root)` にして保存
4. 数分後に `https://<ユーザー名>.github.io/tcg-collection/` で開けます

この時点で、手動登録・CSV/JSON 入出力・ローカル自動保存は使えます。

### PC で動作確認する場合

`index.html` をダブルクリックで開くと ES モジュールや IndexedDB が動きません。簡易サーバーを使ってください。

```bash
cd tcg-collection-app
python -m http.server 8000
# → http://localhost:8000/ を開く
```

## 2. Google 連携（Gmail 取り込み・ドライブ保存）

Google Cloud Console で OAuth クライアントを1つ作ります（無料）。

1. https://console.cloud.google.com/ で新しいプロジェクトを作成
2. **API とサービス → ライブラリ** で **Gmail API** と **Google Drive API** を有効化
3. **OAuth 同意画面**（Google Auth Platform）を設定
   - User Type: 外部 / アプリ名・メールアドレスを入力
   - スコープ: `gmail.readonly` と `drive.file` を追加
   - **テストユーザー** に自分の Gmail アドレスを追加（公開ステータスは「テスト」のままで OK）
4. **認証情報 → 認証情報を作成 → OAuth クライアント ID**
   - 種類: **ウェブ アプリケーション**
   - 承認済みの JavaScript 生成元: `https://<ユーザー名>.github.io`（ローカル確認するなら `http://localhost:8000` も）
   - リダイレクト URI は不要
5. 表示された **クライアント ID**（`xxxx.apps.googleusercontent.com`）をアプリの「設定 → Google 連携」に貼り付け

> テスト状態のアプリでは、ログイン時に「Google はこのアプリを確認していません」と表示されます。自分で作ったアプリなので「続行」で進めてください。
> クライアント ID は公開されても問題ない値です（シークレットは不要・使用しません）。

### スコープについて

- `gmail.readonly` … 購入メールの読み取りのみ。メールの変更・送信はしません
- `drive.file` … このアプリが作成したファイル（`tcg-collection-backup.json`）にだけアクセスします。他のドライブのファイルは見えません

## 3. Gemini（任意）

1. https://aistudio.google.com/apikey で API キーを作成
2. 「設定 → AI（Gemini）」に貼り付け。モデル名は既定で `gemini-2.5-flash`（使えなくなったら新しいモデル名に変更）

API キーはその端末のブラウザ（localStorage）にのみ保存され、バックアップファイルには含まれません。

## 4. カードラッシュ連携（任意・PC版 Chrome）

カードの**正式名・レアリティ・番号・セット型番・画像**を [カードラッシュ](https://www.cardrush-pokemon.jp/) から取得できます。

カードラッシュは外部のサイトから直接読み込めず（CORS 非対応）、Google Apps Script などのサーバーからのアクセスもボット対策で拒否されます。そこで、**PC版 Chrome に専用の拡張機能を入れ、普段使っている Chrome 自身で取得**します。スマホからは使えません（PC で照合した結果はバックアップ経由でスマホにも反映できます）。

### 拡張機能の入れ方

1. このリポジトリの [ZIP](https://github.com/snowpa/tcg-collection-app/archive/refs/heads/main.zip) をダウンロードして展開（または `git clone`）
2. Chrome で `chrome://extensions` を開き、右上の **デベロッパー モード** をオン
3. **パッケージ化されていない拡張機能を読み込む** → 展開したフォルダの中の **`chrome-extension`** フォルダを選ぶ
4. アプリを再読み込みし、「設定 → カードラッシュ連携」が「接続済み」になっていれば完了（「接続テスト」で検索も確認できます）

- 拡張機能がアクセスするのは **カードラッシュと晴れる屋2のみ**、アプリから呼び出せるのは **このアプリのページ（`snowpa.github.io`）のみ**です
- 拡張機能の ID は固定（`cblfamljonlennohgbbpkbnhpeaapfjf`）なので、アプリが自動で見つけます
- 同じ検索は6時間キャッシュして、カードラッシュへのアクセスを最小限にしています
- 「ボット確認が表示されています」と出たときは「カードラッシュを開く」で一度サイトを表示してから再試行してください
- 拡張機能を更新したときは、新しいファイルに置き換えてから `chrome://extensions` で拡張機能の 🔄（再読み込み）を押してください（ZIP から入れた場合は ZIP をダウンロードし直して同じフォルダに上書き）

### 使い方

| 場所 | 操作 |
| --- | --- |
| カード詳細 | 「🔎 カードラッシュから取得」→ 候補から選ぶと、名前・レアリティ・番号・型番・画像を反映 |
| Gmail 取り込み | 候補ごとの「🔎 照合」で選んでおくと、追加時に正式名と画像で登録 |
| コレクション | 「選択」で複数選び「🔎 カードラッシュで照合」→ 1枚ずつ候補を選ぶと保存して次のカードへ（「このカードを飛ばす」も可） |

- 検索語はカード名と番号から自動で作ります。カードラッシュの検索はすべての語を含む商品だけを返すため、「名前 番号（例: マリィ 198/190）」→「番号」→ 名前の語を減らす、の順に見つかるまで試します
- 番号が一致する商品を先頭に、中古の状態ランク付き（〔状態B〕など）・鑑定品・売り切れの商品を後ろに並べます。売り切れ商品でも、保存する画像に「SOLD OUT」の文字は入りません
- 画像は端末に保存されます（取得できなかった場合はカードラッシュの画像を直接表示）
- 個人のコレクション管理の範囲で、カードラッシュの利用規約に沿って利用してください

### 相場（カードラッシュ販売価格ベース）

ホームの「相場を更新」で、カードラッシュから同じカードの**状態別・鑑定別の販売価格の一覧**を取得して保存し、手持ちの状態に合わせて**アプリ内で相場を計算**して**相場総額**を表示します（拡張機能 v1.1.0 以上が必要）。状態評価・欠陥・鑑定・PSA の割合の設定を変えても、通信せずにすぐ再計算されます。

| 手持ちの状態 | 使うカードラッシュの価格 |
| --- | --- |
| PSA 鑑定品 | PSA10 の販売価格 × グレード別の割合（PSA10 100%・9 40〜60%・8 20〜35%・7 12〜20%・6 8〜15%・5 6〜10%・4 4〜7%・3 3〜5%・2 2〜4%・1 1.5〜3%）。幅のどこ（下限・中央・上限）を使うかは設定画面で選択（初期値は中央）。PSA10 の販売がなければ同じグレードの販売価格 |
| その他の鑑定品（BGS・ARS など） | 同じ鑑定の販売価格（「状態難」付きは除く） |
| 鑑定品ではない・総合評価 S・A | 通常（無印）の販売価格 |
| 鑑定品ではない・総合評価 B | 〔状態A-〕の販売価格 |
| 鑑定品ではない・総合評価 C | 〔状態B〕の販売価格 |
| 鑑定品ではない・総合評価 D | 〔状態C〕の販売価格 |
| 未評価 | 欠陥チェックから判断（欠陥なし → 通常、軽微 → 状態A-、目立つ → 状態B、重度・折れ/へこみ → 状態C） |
| 未開封 | 未開封の商品の価格 |

- 名前・番号・型番・レアリティが一致する商品だけを使います。カードラッシュがかっこ書きで付けている版違い（`(R仕様)` `(25thミラー)` `(1ED)` `(アンリミ)` など）は、購入時の商品名・メモにある手がかり（1ED、ミラーなど）で選び、手がかりがなければ通常版にします
- 該当する状態の商品がない場合は、別の状態の価格を掛け率（通常 100%・状態A- 90%・B 75%・C 50%）で換算した **推定** です。PSA の割合（下限・中央・上限）は設定画面で選べます
- **要確認**: 番号がなく名前だけで商品を特定したもの、購入額の10倍以上になったもの。総額の内訳に「うち要確認」として分けて表示します。カード詳細で参照先の商品を確認し、違う場合は「🔎 カードラッシュから取得」で正しい商品を選んでから相場を取り直してください
- 同じ名前のカードが複数あって特定できないもの（番号なしのカードに多い）は相場なしになります。カードラッシュで照合して番号・型番を入れると取得できます
- 取得できないときは、名前・番号・型番・レアリティのどれが一致しなかったかと、カードラッシュ側にある番号・型番・レアリティを表示します
- 未開封のカードで未開封の販売がない場合は、開封品の価格で代用します（根拠に表示）
- **晴れる屋2（予備）**: カードラッシュで同じカードが見つからない場合は、[晴れる屋2](https://www.hareruya2.com/) を「名前＋番号」で1回だけ検索し、同じ方法で相場を計算します（拡張機能 v1.2.0 以上）。根拠に「（晴れる屋2の販売価格）」と表示し、参照リンクは晴れる屋2の商品ページです。晴れる屋2はアクセス回数の制限が厳しいため、問い合わせは3秒以上あけ、制限にかかった場合は5分間問い合わせを止めて、そのカードは次回の更新で取り直します。晴れる屋2の robots.txt は検索ページを自動巡回の対象外にしているので、個人の利用の範囲で、まとめて大量に更新しすぎないようにしてください
- 価格一覧の取り直しが必要なのは、カード自体（名前・番号・型番・レアリティ・未開封）を変えたときと、24時間以上たったときだけです。
- カード詳細で所持カードを**保存するときにも自動で取得**します（未取得・カード自体の変更・24時間経過のときだけ。拡張機能がない環境では飛ばして保存します）「すべて取り直す」で全件を再取得、複数選択から「💴 相場を更新」で選んだカードだけ取得できます
- **売却概算** = 相場（カードラッシュ売値）× 70%（設定画面で変更可）。ホームの総額、一覧、リスト表示、カード詳細、CSV に表示します
- 販売価格は買取価格ではありません。あくまで目安です

## バックアップと復元

状態の写真はバックアップに含まれるため、写真が多いとバックアップファイルが大きくなります。

| 方法 | 使い方 |
| --- | --- |
| Google ドライブ | 右上の「バックアップ」ボタンか設定画面の「ドライブに保存」。一度ログインすると、その後1時間は変更のたびに自動保存（設定で OFF 可） |
| ローカル自動保存 | PC版 Chrome / Edge で「自動保存するファイルを指定」。以後は変更のたびに上書き。OneDrive 等の同期フォルダ内を指定すると二重の備えに |
| JSON | 「JSON を書き出す」で手動保存。スマホではこちら |
| CSV | Excel / スプレッドシートで見る用 |

- **マージ**: 両方のデータを合わせます。同じカードは更新日時が新しい方を採用（削除も反映）。複数端末での同期に使えます
- **上書き復元**: 端末のデータをバックアップの内容で置き換えます

ホーム画面には、7日以上バックアップしていない場合に通知が出ます。

### 旧スプレッドシートからの移行

スプレッドシート「ポケモンカード購入履歴」を **ファイル → ダウンロード → CSV** で保存し、「取り込み → CSV から取り込む」で読み込みます。
「予測名称」列（例: `マリィ (SR, S4a シャイニースターV, 198/190)`）はカード名・レアリティ・セット・番号に分解されます。
メールリンクが一致するメールは、以後 Gmail スキャンでも「取込済み」として扱われます。
